# No paid APIs: Groq's free tier for answers, in-session drafting and judging

The project must run without paying for any API. Answers are therefore generated by an open-weight model on Groq's free tier (`openai/gpt-oss-120b` at low reasoning effort, falling back to `openai/gpt-oss-20b`; key `GROQ_API_KEY` in `.env`), behind the same answering-LLM interface as before, with a local Ollama model as an optional offline fallback. Embedding and reranking already run locally. The two remaining LLM jobs are offline tasks rather than parts of the running system, and the developer's AI coding assistant (Claude Code) does them in-session instead of through an API:
- drafting candidate Evaluation Pairs, which the developer then reviews;
- judging Faithfulness Verdicts, with 20 hand-checked by the developer to measure agreement.

## Considered Options

- **A paid hosted model (originally Claude via the Anthropic API) for answering, drafting and judging:** the best quality and fully scriptable, but rejected because it isn't free.
- **Ollama only:** free and offline, but a laptop-sized model is slower and weaker, which puts the under-2-second latency target at risk. It is kept as a fallback, not the default.
- **Using the answering model as its own faithfulness judge:** free, but a model grading its own answers is a weak check. Judging is done by a different model (Claude Code) and measured against the developer's own verdicts.

## Consequences

- **Faithfulness is reproducible from a file, not by re-running a judge.** The in-session verdicts are committed, and the verdict shares and agreement rate are recomputed from them by script. Re-judging after the answers change needs a new session. This is the one exception to ADR-0001's rule that every headline number comes from a re-runnable script, and the README must say so.
- **Free-tier rate limits apply.** Answering the whole Evaluation Set (`--answer`) and the latency measurement must be paced and retry on rate-limit errors. Latency includes the network round trip to Groq, and the README reports which provider and model were measured.
- **Groq model names may change.** The model is a setting, not code.
- **Tests never call any LLM service.** The LLM is always a fake.
